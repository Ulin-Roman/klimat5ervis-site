## Реализация

Оригиналы сохранены. Worker создаёт WebP q82 до 360/720/1280 px по длинной стороне без увеличения маленьких исходников, учитывает EXIF и прозрачность. Read-only images-render.php подключает srcset/sizes к главной, каталогу/товарам и корзине. Zoom остаётся на оригиналах; миниатюры меняют адаптивное главное фото. Если вариант отсутствует или mtime/размер исходника изменились, используется исходник. Свежесть проверяется по метаданным, не полным хешем содержимого.

Генерация защищена существующей административной авторизацией, superuser/read_only/dismissed-проверками, POST CSRF и mutex. Служебные файлы и временные записи защищены PHP-префиксом; проверенный прямой HTTP-доступ отклонён без выдачи содержимого. Пароли, сессии и данные хостинг-аккаунта в документацию не включены.

## Финальные ограничения

| Параметр | Значение |
| --- | ---: |
| Выходные файлы | 600 MiB |
| Суммарный CPU worker | 2400 с |
| Верхняя граница памяти worker | 256 MiB |
| Пакет между изображениями | 2 CPU / 4 wall секунды |
| Групп за пакет | не более 20 |
| Пауза интерфейса | 1000 мс |

Лимиты пакета проверяются между изображениями; один decode/encode может длиться дольше. CPU worker не равен расходу всего аккаунта. Свободное место и резерв 16 MiB перед новым вариантом проверяются отдельно.

Dirty accounting v1 сохраняет dirty до публичной записи. Нормальный commit атомарно сохраняет байты, курсор и clean. Миграция старого state, dirty recovery и prepare делают полный пересчёт, включая orphan/temp/config; обычные clean-пакеты используют счётчик. На сервере проверены первый migration full scan и последующие clean без полного обхода. Итог: accounting_version=1, dirty=false, full_scan=false. Ошибка очистки temp останавливает пакет с dirty. ## Что осталось

Будущие загрузки автоматически не обрабатываются: cron/upload-hook/фоновая служба не установлены. Повторная генерация новых/изменённых исходников требует отдельной автоматизации и проверки. Независимая анонимная/non-superuser сессия не создавалась; EXIF/alpha края проверены статически, без синтетических файлов на рабочем сайте. Учёт предполагает эксклюзивный каталог worker и покрывает сбой PHP-процесса; абсолютная устойчивость к потере питания без fsync не заявляется.
